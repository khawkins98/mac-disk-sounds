# Contributing to Mac Disk Sounds

Thanks for wanting to make computers sound worse in the best possible way.
This is a small hobby project, so the process is light. These notes cover what
you need to know to get a change merged.

## Getting started

You need Node.js 22.12 or newer; CI uses Node 24.

```bash
git clone https://github.com/khawkins98/mac-disk-sounds
cd mac-disk-sounds
npm install
npm start
```

If `npm start` complains that Electron failed to install, run
`node node_modules/electron/install.js` once.

## Before you open a pull request

Run the same checks CI runs:

```bash
npm run lint
npm test
node scripts/check-build-config.mjs
node scripts/smoke-monitor.mjs   # reads your real disk for about 5 seconds
```

If you changed packaging, the icons or anything under `build/`, also run a
local package build, e.g. `npx electron-builder --dir --publish never`.

Then:

- Keep pull requests focused: one change or one coherent set of changes.
- Add or update tests for logic you touch. The pure modules are
  `src/main/activity.js`, `disk-parsers.js`, `settings.js`, `login-item.js`,
  `tray-menu.js`, `tray-click.js` and `tray-host.js`, and they are easy to
  test with `node --test`; see `test/`.
- Add a line under **Unreleased** in [CHANGELOG.md](CHANGELOG.md) describing
  the change from a user's point of view.
- Say in the pull request what you tested and on which OS. Most contributors
  only have one platform, and that's fine; just say which one.

## How the app fits together

```
src/main/        main process: lifecycle, windows, tray, settings,
                 launch at login, disk monitor and activity model
src/preload.cjs  the only bridge between the pages and main
src/renderer/    settings window and the hidden audio window
assets/          sounds and tray icons
build/           app icons used by electron-builder
scripts/         icon generators, build config check, disk monitor smoke test
```

- **Disk monitor** (`src/main/disk-monitor.js`, parsers in `disk-parsers.js`):
  one backend per platform. On Linux it reads `/proc/diskstats`, on macOS it
  runs one long-lived `iostat`, and on Windows it runs one long-lived
  PowerShell/CIM process with `typeperf` as a fallback. Don't add anything
  that spawns a process on every tick.
- **Activity model** (`src/main/activity.js`): turns byte rates into
  active/idle and a level from 1 to 5. Changes to thresholds or hysteresis
  need tests for both sustained load and periodic background writers.
- **Audio** (`src/renderer/audio.js`, `audio-host.js`): plain Web Audio in a
  hidden window that lives as long as the app does.

## Rules worth knowing

- **No new runtime dependencies** without a very good reason. The app
  currently ships none, which is what keeps Electron upgrades painless.
- **Security settings stay on.** That means context isolation, the sandbox,
  the strict Content Security Policy (no inline scripts or styles, no remote
  content) and checks on who sends each IPC message. New IPC channels go
  through the preload bridge and are validated in main. `openExternal` only
  allows the hosts already on its allowlist.
- **No network access at runtime**, apart from links the user clicks.
- **Sounds:** the files in `assets/sounds/` are from Pixabay and are not
  covered by the MIT licence. New sounds must have a licence that allows
  redistribution inside the app. Record the source, author and licence in
  [assets/sounds/CREDITS.md](assets/sounds/CREDITS.md).
- **Icons** are generated by `scripts/make-app-icon.mjs` and
  `scripts/make-tray-icons.mjs`. Change the script and regenerate the files;
  don't edit the images by hand, because the tests check they match the
  scripts.

## Reporting bugs

Open an issue with your OS and version, the app version (shown in the tray
menu), what you expected and what happened. For "it doesn't click" problems,
the output of `node scripts/smoke-monitor.mjs` from a clone of the repo helps
a lot.

## Releasing (maintainers)

1. Move the **Unreleased** entries in `CHANGELOG.md` under a new version
   heading, with the date, and update the compare links at the bottom.
2. Set the same version in `package.json` with
   `npm version <x.y.z> --no-git-tag-version`.
3. Merge that to `main`, then tag the merge commit and push the tag:
   `git tag v<x.y.z> && git push origin v<x.y.z>`.

The release workflow then checks that the tag matches `package.json`, runs
lint and tests, and creates a draft release with that version's CHANGELOG
section as its notes. It builds macOS (universal), Windows and Linux, and
publishes the release only once all three have uploaded. Versions with a `-`
(e.g. `1.2.0-beta.1`) are published as pre-releases.
